# مدرسه‌یار | MadresehYar

**ساختهٔ [شرکت دیس وب](https://disweb.ir) — disweb.ir**

سامانهٔ فارسی و ماژولار مدیریت مدرسه با **Node.js / Express، React، SQLite و فونت محلی وزیرمتن**. این مخزن یک برنامهٔ قابل اجرا با API و دادهٔ ماندگار است، نه صرفاً قالب داشبورد.

**نسخهٔ ۱.۲.۰** — نسخهٔ کاملِ ظاهر و نصب: **پالت رنگی قابل‌تغییر از تنظیمات مدیر** (۹ پالت + اندازهٔ فونت با پیش‌نمایش زنده)، بازسازی کنتراست همهٔ رنگ‌ها (خوانایی تأییدشده)، فهرست‌های کشویی **جست‌وجو‌پذیر** برای انتخاب دانش‌آموز/معلم/کتاب، **موبایل‌فرند** سراسری با کارت‌های حضور و غیاب و نوار ذخیرهٔ شناور، و نصب بی‌دردسر بستهٔ دمو روی cPanel. نسخهٔ ۱.۱ پیشنهادهای بازبینی مدیر مدرسه را کامل پیاده کرده بود: بازیابی پشتیبان، پل پیامک/ایمیل، رضایت ولی، کارنامهٔ چاپی، ثبت گروهی نمره، اقساط و جریمهٔ دیرکرد، مرخصی با گردش تأیید، ملاقات اولیا، ارتقا و بایگانی پایان سال، خروجی وزارتی، ورودی xlsx/PDF، مرتب‌سازی و عملیات گروهی، **انتخاب‌گر تاریخ جلالی**، کتابخانهٔ کامل، کارکنان، «کارهای امروز من»، روند تحصیلی، صفحهٔ وضعیت سرویس و گزارش خطا با کد پیگیری.

## این نسخه چه دارد؟

- **۱۷ ماژول و ۱۸۸ قابلیت ثبت‌شده**: عملیات مشاهده/ثبت/ویرایش/حذف ایمن در ۳۳ نوع پرونده، به‌علاوهٔ workflow‌های حضور، تیکت، تکلیف، مالی، کتابخانه، ملاقات، تحلیل و مدیریت. [فهرست دقیق و مسیر API](docs/FEATURES.md).
- چهار نقش **مدیر، معلم، دانش‌آموز و ولی**؛ محدودسازی رکوردها در سمت سرور، نه فقط پنهان‌کردن منو.
- معلم راهنمای کلاس و تخصیص چند معلم از طریق برنامهٔ هفتگی، دانش‌آموزان کلاس، پروندهٔ فردی، اطلاعات اولیا و تماس اضطراری؛ حساب مستقل با رمز موقت و الزام تغییر رمز.
- حضور روزانه و تاریخچه، ثبت گروهی، غیبت موجه و تأخیر، یادداشت و اعلان غیبت داخل سامانه.
- **مرخصی و غیبت موجه** با گردش تأیید: ولی یا مدرسه درخواست می‌دهد، مدرسه تأیید می‌کند و روزهای گذشته‌شده خودکار «موجه» ثبت می‌شوند.
- **ملاقات اولیا و مربیان** با بازه‌های زمانی، ظرفیت و نوبت‌دهی آنلاین؛ به‌همراه کارکنان غیرآموزشی، حضور و حقوق کارکنان.
- **رضایت ولی برای پردازش دادهٔ دانش‌آموز** با وضعیت، تاریخ و یادداشت در پرونده.
- تیکت خصوصی به مدیر/معلم مجاز، پاسخ، وضعیت، اولویت و پیوست امن.
- دروس، برنامهٔ هفتگی با کنترل تداخل، تکالیف و تحویل/ارزیابی، آزمون‌ها و نمرات با معدل وزنی.
- شهریه، رسید واریز، کنترل بیش‌پرداخت، ماندهٔ خودکار، هزینه‌ها و حقوق همکاران؛ **تخفیف، اقساط، جریمهٔ دیرکرد و گزارش بدهکاران با سن بدهی**.
- کتابخانه با **رزرو، تمدید، جریمهٔ دیرکرد و گزارش امانت‌های دیرکرد**؛ تجهیزات، سرویس، مهمانان، سلامت، سوابق رفتاری و مشاوره.
- **کارنامهٔ دوره** با معدل وزنی، درصد حضور و نسخهٔ چاپی (`/print/cards`)، **خروجی XLSX** در تمام فهرست‌ها و گزارش‌ها، **خروجی استاندارد وزارتی/سناد**، **روند تحصیلی و حضور هر دانش‌آموز** و **ارتقا/تکرار/فارغ‌التحصیلی پایان سال با بایگانی خودکار**.
- **پل پیامک و ایمیل** برای غیبت، نمره، شهریه، تکلیف و اطلاعیه؛ با صف ارسال، تلاش دوباره و سرویس‌دهندهٔ کاوه‌نگار/وب‌هوک.
- **صفحهٔ وضعیت سرویس** و **گزارش مشکل توسط کاربر** با کد پیگیری؛ **بازیابی پشتیبان از داخل سامانه** با تأیید رمز مدیر و نسخهٔ امنیتی خودکار.
- تقویم شمسی، اطلاعیهٔ هدفمند، جست‌وجو، گزارش، مرتب‌سازی ستون‌ها و عملیات گروهی ردیف‌ها، کاربران، رویداد مدیریتی و پشتیبان SQLite.
- کلید ماژول و کلید مستقل هر قابلیت؛ خاموش‌شدن عملیات در UI و API و حفظ داده‌های قبلی. هستهٔ احراز هویت و مدیریت کلیدها برای جلوگیری از قفل‌شدن سامانه خاموش نمی‌شوند.
- رابط راست‌به‌چپ، واکنش‌گرا، آیکون‌های SVG، وزیرمتن متغیر میزبانی‌شده به‌صورت محلی و بدون CDN.

## اجرای سریع دمو

پیش‌نیاز: **Node.js 20.19+ یا 22.12+**؛ Node.js 22.12+ پیشنهاد می‌شود.

```bash
npm ci
npm run dev
```

رابط روی `http://localhost:5173` و API پشت پراکسی Vite قرار می‌گیرد. کد مرورگر فقط از مسیرهای نسبی `/api` استفاده می‌کند. برای اجرای یک‌سروری:

```bash
npm run build
PORT=3000 npm run preview
```

در حالت توسعه، دمو فقط برای پایگاه‌دادهٔ نصب‌نشده ساخته می‌شود. داشبورد اولیه به حساب مدیر نمایشی وارد می‌شود. از منوی حساب بالا می‌توانید نقش را تغییر دهید؛ یا خارج شوید و با حساب‌های زیر وارد شوید:

| نقش       | نام کاربری | رمز نمایشی    |
| --------- | ---------- | ------------- |
| مدیر      | `admin`    | `School@1405` |
| معلم      | `teacher`  | `School@1405` |
| دانش‌آموز | `student`  | `School@1405` |
| ولی       | `parent`   | `School@1405` |

دمو شامل **۲۴۰ دانش‌آموز، ۱۸ معلم، ۱۲ کلاس، ۱۸۰ زنگ برنامهٔ هفتگی، حدود سه هفته حضور، ۱۲۰۰ نمره، شهریه و رسید، تکلیف و پاسخ، اطلاعیه، رویداد، مدارک و تیکت** است. همهٔ اسامی و شماره‌ها نمونه‌اند. تغییرات دمو نیز در `data` ذخیره می‌شوند.

> حساب‌های نمایشی و ورود بدون رمز در تولید فعال نیستند. برنامه اجازهٔ اجرای `DEMO_MODE=true` همراه `NODE_ENV=production` را نمی‌دهد. دادهٔ دمو را برای مدرسهٔ واقعی، از یک پایگاه‌دادهٔ تازه و ویزارد وارد کنید؛ فایل دیتابیس دمو را به هاست واقعی نبرید.

## نصب واقعی و cPanel

**cPanel باید Setup Node.js App / Application Manager با Node.js داشته باشد. هاست صرفاً PHP پشتیبانی نمی‌شود.**

راهنمای کامل، تنظیم Passenger، تک‌فرآیندی، HTTPS، نصب بدون SSH، پشتیبان و بازیابی: **[docs/CPANEL.md](docs/CPANEL.md)**.

خلاصهٔ نصب:

```bash
npm ci
npm run build
cp .env.example .env
# .env: NODE_ENV=production, DEMO_MODE=false, INSTALL_TOKEN=<random 24+ chars>
# نصب در زیرپوشه (مثلاً /school): BASE_PATH=/school — هم برای build و هم برای اجرا
npm start
```

**نصب در ساب‌دایرکتوری:** مقدار `BASE_PATH=/school` را هم پیش از `npm run build` و هم در `.env` زمان اجرا تنظیم کنید. Vite آدرس دارایی‌ها را با همان پیشوند می‌سازد، API در `‎/school/api` سرو می‌شود، کوکی نشست به همان مسیر محدود می‌ماند و مسیر ریشه به `/school/` هدایت می‌شود. جزئیات در [docs/CPANEL.md](docs/CPANEL.md).

مسیر `/install` ویزارد پنج‌مرحله‌ای دارد: بررسی آمادگی، مدرسه، مدیر، ماژول‌ها و پایان. در نبود `INSTALL_TOKEN`، توکن خصوصی در `data/install.key` ساخته می‌شود. نصب یک‌باره است و بدون توکن انجام نمی‌شود.

اگر در نصب واقعی دادهٔ نمونه را انتخاب کنید، حساب‌های نمونه **غیرفعال‌اند و رمز عمومی دمو ندارند**. مدیر باید رمز حساب موردنظر را بازنشانی و سپس حساب را فعال کند. حساب مدیرِ انتخاب‌شده در ویزارد فعال می‌ماند.

### بستهٔ آمادهٔ cPanel

```bash
npm run package:cpanel   # artifacts/madresehyar-cpanel.zip  (نسخهٔ واقعی)
npm run package:demo     # artifacts/madresehyar-demo-cpanel.zip + راهنمای داخل بسته
```

فایل `artifacts/madresehyar-cpanel.zip` شامل رابط ساخته‌شده، API، منابع، راهنما و lockfile است؛ **شامل `.env`، دیتابیس، پیوست‌ها، توکن نصب، `.git` و `node_modules` نیست**. روی هاست فقط `npm ci --omit=dev` لازم است؛ نیازی به اجرای Vite یا build روی هاست ندارید.

## فروش ماژولار و لایسنس

سامانه می‌تواند ماژول‌به‌ماژول فروخته شود: **قیمت پایه برای هستهٔ مدرسه + قیمت هر ماژول افزودنی**، لایسنس **مادام‌العمر** و بدون اشتراک. لایسنس با کلید خصوصی فروشنده (Ed25519) امضا می‌شود و روی هاست مدرسه فقط با کلید عمومی بررسی می‌گردد؛ **بدون تماس با سرور فروشنده** و بدون نیاز به اینترنت.

```bash
npm run license:make                                            # جادوگر ساده (متن لاتین/fingilish)
# یا به‌صورت دستی برای خودکارسازی:
npm run license:keygen -- --out ./license-keys                 # یک‌بار برای همیشه
npm run license:issue  -- --customer "دبیرستان نمونه" --edition standard
npm run license:inspect -- --license ./license-keys/MY-1405-0007.json
```

بسته‌بندی (`npm run package:cpanel`) اگر پوشهٔ `license-keys` وجود داشته باشد، **کلید عمومی فروشنده را خودکار داخل بسته** می‌گذارد؛ مشتری فقط `license.json` را در پوشهٔ دادهٔ خود می‌گذارد و `LICENSE_MODE=on` می‌کند.

ماژول‌های نخریده در پنل با نشان «خریدنی» دیده می‌شوند، سوییچشان غیرفعال است و API هم با کد `LICENSE_REQUIRED` پاسخ می‌دهد. `LICENSE_MODE=off` (پیش‌فرض) همهٔ ماژول‌ها را باز می‌گذارد؛ برای نسخهٔ فروشی `on` بگذارید. جزئیات فروش، قیمت‌گذاری، قرارداد و گردش کار مشتری در [docs/LICENSING.md](docs/LICENSING.md).

## آزمون و کیفیت

```bash
npm test                    # ۱۵۱ آزمون API، مجوز، CRUD، جلالی، xlsx، لایسنس/جادوگر و استقرار
npm run build               # ساخت صفحات به‌صورت code-split
npm audit --omit=dev         # بررسی وابستگی‌ها
npx playwright install chromium
npm run test:e2e             # ۲۴ جریان مرورگر، دادهٔ مستقل در مسیر موقت
npm run format:check
```

آخرین نتیجه: **۱۵۱ آزمون API/بانک و ۲۶ جریان مرورگر، بدون شکست**. دو دور نخست بازبینی ۵۲ ایراد منطقی/دسترسی را اصلاح کرد؛ دور سوم همهٔ موارد [نقد مدیر مدرسه](docs/PRINCIPAL-REVIEW.md) را پیاده کرد و ۱۳ آزمون یکپارچه و ۷ جریان مرورگر تازه به مجموعه اضافه شد؛ سپس فروش ماژولار با لایسنس محلی اضافه و ۷ آزمون لایسنس نوشته شد. جزئیات در [docs/QUALITY.md](docs/QUALITY.md).

برای تست مرورگر یک وب‌سرور جداگانه در پورت ۳۱۰۰ با دادهٔ موقت اجرا می‌شود؛ به دادهٔ اجرای عادی دست نمی‌زند. اگر Chrome از قبل دارید، می‌توانید `CHROMIUM_EXECUTABLE_PATH` را تنظیم کنید.

گزارش دقیق آزمون‌ها و حدود تأیید: [docs/QUALITY.md](docs/QUALITY.md).

## معماری

```text
app.cjs                    # ورودی CommonJS سازگار با Passenger
server/
  index.js                 # اجرای برنامه و نصب اولیه
  app.js                   # Express، امنیت، مسیرها و رابط production
  database.js              # SQLite/WASM، تراکنش، نوشتن اتمیک و قفل تک‌فرآیندی
  security.js              # نشست، CSRF، scope نقش‌ها، اعتبارسنجی و CSV امن
  resources.js             # CRUD معتبر و قوانین تجاری ۳۳ نوع پرونده
  modules/                 # حضور، تیکت، آموزش، فایل، تنظیمات، گزارش و نصب
shared/catalog.js          # تعریف واحد ماژول/قابلیت/فیلد/نقش برای UI و API
src/
  components/              # چیدمان، فرم، مودال، نمودار، کنترل‌ها
  pages/                   # پنل‌های فارسی و ویزارد
  context.jsx              # حساب، پیکربندی و درخواست‌ها
scripts/                   # بستهٔ نصب، فهرست قابلیت و بازیابی مدیر
```

برای افزودن پروندهٔ جدید، تعریف فیلدها و دسترسی را در `shared/catalog.js` اضافه کنید؛ فرم و چهار API از همان قرارداد ساخته می‌شوند. قابلیت‌های پیچیده در `server/modules` و صفحهٔ اختصاصی قرار دارند. پس از تغییر کاتالوگ، `npm run features` و تست‌ها را اجرا کنید.

## بهینه‌سازی و حدود نسخهٔ اول

- صفحات lazy-load، فونت متغیر با کش محلی، Gzip، کش طولانی فایل‌های hashدار؛ دادهٔ خصوصی `no-store` است.
- فیلتر و صفحه‌بندی در سرور، SQL پارامتری و شاخص روی رابطه‌ها و تاریخ‌ها؛ فرم CSV حداکثر ۵۰ ردیف و فایل پیش‌فرض حداکثر ۵ مگابایت.
- SQLite از طریق SQL.js نیاز به MySQL یا کامپایل افزونهٔ بومی ندارد. بانک در حافظهٔ **یک فرآیند** نگهداری و هر تغییر به‌صورت اتمیک روی دیسک ذخیره می‌شود؛ قفل مانع اجرای دو نویسنده می‌شود.
- **این نسخه تک‌مدرسه‌ای و تک‌فرآیندی است.** برای چند مدرسه، چند worker، حجم بسیار زیاد و مقیاس افقی، باید لایهٔ داده به PostgreSQL/MySQL و فایل‌ها به ذخیره‌سازی مشترک مهاجرت کند. ادعای تست بار هزاران کاربر نداریم.
- پرداخت‌ها **ثبت رسید واقعی واریز توسط مدیر** هستند؛ اتصال مستقیم به درگاه بانکی، اپ بومی موبایل، آزمون آنلاین سؤالی، MFA و ارسال مستقیم به سامانهٔ سناد/شاد پیاده نشده‌اند. پیامک و ایمیل از طریق سرویس‌دهنده (کاوه‌نگار یا وب‌هوک سازمانی) و خروجی استاندارد فایل وزارتی انجام می‌شود.
- گزارش معدل از ارزشیابی‌های ثبت‌شده و مجاز محاسبه می‌شود؛ برای کارنامهٔ رسمی مصوب، امضای مدرسه و تأیید اداره لازم است. یک حساب ولی به یک دانش‌آموز متصل می‌شود؛ چندفرزندی در این نسخه نیست.
- تاریخ‌ها در API میلادی ISO و زمان‌ها UTC ذخیره می‌شوند؛ **ورودی و نمایش تاریخ کاملاً شمسی است** و مقدار ذخیره‌شده ISO باقی می‌ماند تا سازگاری داده حفظ شود.
- بکاپ SQLite شامل پیوست‌ها نیست؛ `data/uploads` را جداگانه پشتیبان بگیرید. [امنیت و بهره‌برداری](docs/SECURITY.md).
- قبل از ورود اطلاعات واقعی کودکان، HTTPS، مجوز پوشه‌ها، نسخهٔ پشتیبان، بازیابی و سیاست دسترسی مدرسه را در محیط خود بررسی کنید؛ آزمون‌های این مخزن جایگزین ممیزی امنیت و تست بار عملیاتی نیستند.
