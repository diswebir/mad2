# وضعیت آزمون و پوشش نسخهٔ ۱.۱

آخرین بررسی: **۱ اکتبر ۲۰۲۶**. محیط اجرا Node.js 22.22.3، Vite 7.3.6 و Chromium 153 headless است.

## نتایج

| بررسی                   | نتیجه                                                                |
| ----------------------- | -------------------------------------------------------------------- |
| آزمون API / پایگاه‌داده | ۱۴۰ آزمون موفق، بدون شکست                                            |
| آزمون مرورگر            | ۲۴ جریان موفق، بدون شکست                                             |
| ساخت production         | موفق؛ صفحات code-split و فونت محلی                                   |
| نصب در ساب‌دایرکتوری    | ۴ آزمون مسیر پایه (`BASE_PATH`) موفق، شامل ریدایرکت و کوکی دامنه‌دار |
| npm audit               | آسیب‌پذیری شناخته‌شدهٔ گزارش‌شده: صفر                                |
| بررسی ZIP استخراج‌شده   | اجرا با `npm ci --omit=dev`، نصب production و بازیابی CLI مدیر موفق  |
| فرمت                    | Prettier check موفق                                                  |

`npm test` شامل آزمون‌های سطح بالا و زیرآزمون‌های پرونده است؛ عدد ۱۴۷ مجموع آزمون‌ها و زیرآزمون‌هاست (دور دوم ۲۹ آزمون کاوش چند‌نقشی، دور سوم ۱۳ آزمون قابلیت‌های تازه و ۴ آزمون استقرار، و در گام بعد ۷ آزمون لایسنس/فروش ماژولار اضافه شد). عدد «۱۸۸ قابلیت» تعداد آزمون نیست و همهٔ قابلیت‌ها آزمون مستقل یک‌به‌یک ندارند.

## API و بانک

- احراز هویت، HttpOnly/Secure/SameSite، نشست و الزام تغییر رمز موقت، لغو نشست‌های قدیمی.
- scope معلم/کلاس و دانش‌آموز/ولی، عدم مشاهده پرونده‌های دیگر، نوشتن مدیریتی و CSRF/Origin.
- **همهٔ ۱۳۲ عملیات CRUD در ۳۳ پرونده** با دادهٔ معتبر و ویرایش/حذف واقعی.
- خاموش‌شدن ماژول و قابلیت در سرور و حفاظت مدیریت کلیدها.
- تاریخ واقعی، ظرفیت کلاس، نمره و نمرهٔ آزمون، تداخل زمان و معلم، موجودی امانت و بیش‌پرداخت.
- ثبت حضور گروهی اتمیک، اعلان غیبت، تاریخچه و scope حضور.
- تیکت خصوصی، گیرندهٔ مجاز، پاسخ و مدیریت، امضای پایه/نوع/حجم فایل، دانلود خصوصی و نام فارسی پیوست.
- تحویل دانش‌آموز و ارزیابی معلم، ماندهٔ شهریه و کنترل مالی، CSV اتمیک و formula-safe.
- حساب ولی مرتبط، ساخت/بازنشانی حساب، جست‌وجو، تقویم، گزارش و اعلان مجاز.
- نصب توکن‌دار یک‌باره، غیرفعال‌بودن حساب نمونه، انتخاب نام مدیر مشابه teacher/student/parent بدون برخورد.
- بکاپ SQLite واقعی، foreign key پس از export، بازشدن روی دیسک پس از بستن، rollback و قفل نویسنده دوم.
- Cookie پارتیشن‌دار پیش‌نمایش HTTPS، حذف Cookie، محدودیت ورود ناموفق جداگانهٔ حساب‌ها روی IP مشترک مدرسه.
- مسیر SPA در پوشهٔ Application مخفی و جلوگیری از انتشار dotfile.
- تخصیص معلم دوم از برنامهٔ هفتگی؛ افزایش کلاس‌های مجاز بدون افشای فیلد خصوصی پروندهٔ همکار.

## ممیزی دورهٔ بازبینی (۴۵ ایراد پیاده‌سازی)

در بازبینی نقش‌ها و گردش‌کارها، ۴۵ ایراد شناسایی و اصلاح شد و برای هر دسته آزمون رگرسیون اضافه شد:

- **پیوند حساب و پرونده:** ویرایش پرونده دیگر حساب دستی‌غیرفعال را فعال نمی‌کرد؛ نشست ولی با غیرفعال‌شدن پرونده باطل نمی‌شد؛ ورود یا فعال‌سازی مجدد حساب بدون پروندهٔ فعال ممکن نبود؛ حذف پرونده همهٔ هویت‌های کاربری وابسته را آزاد می‌کرد. اکنون فعال/غیرفعال‌بودن حساب و وضعیت پرونده دو دروازهٔ مستقل با پیام روشن دارند.
- **مالکیت سوابق آموزشی:** معلم هم‌کلاس می‌توانست تکلیف، ارزیابی و پاسخ همکار را تغییر دهد یا نمره را دوباره ارزیابی کند. اکنون مالکیت رکورد، درس تخصیص‌یافته در برنامهٔ هفتگی و «قفل پاسخ ارزیابی‌شده تا اجازهٔ ارسال مجدد» اعمال می‌شود.
- **تاریخ‌های وابسته به کلاس:** با جابه‌جایی دانش‌آموز، سابقهٔ حضور و نمرهٔ او معنای کلاس را از دست می‌داد. اکنون نمره و حضور، کلاس هنگام ثبت را نگه می‌دارند، انتقال رکورد تاریخی مسدود است و ویرایش‌های مخرب (تبدیل مبلغ/مقیاس، حذف پاسخ‌ها، انتقال صورتحساب پرداخت‌شده و رسید) رد می‌شوند.
- **هستهٔ قابلیت‌ها:** خاموش‌کردن «مشاهدهٔ دانش‌آموز» با `/lookups`، پروندهٔ دانش‌آموز، خروجی‌ها و گزارش‌های تجمیعی دور زده می‌شد؛ اکنون قابلیت‌ها پیش‌نیاز صریح دارند، همهٔ مسیرهای CRUD/گزارش/جست‌وجو آن را رعایت می‌کنند و مسیرهای غیرمجاز در رابط به داشبورد هدایت می‌شوند.
- **اعلان‌ها:** اعلان اطلاعیهٔ زمان‌بندی‌شده به معلمان برنامهٔ هفتگی نمی‌رسید، گاهی چندبار ارسال می‌شد و پس از خاموش‌کردن ماژول مرجع هنوز نمایش داده می‌شد. اکنون تحویل تراکنشی یک‌باره (`notified_at`)، دریافت‌کنندهٔ درست و پنهان‌سازی متناسب با قابلیت مرجع، به‌همراه خواندن تک‌به‌تک و صفحه‌بندی.
- **فایل‌های خصوصی:** مالک فایل پس از پیوست‌شدن، فارغ از دامنهٔ دسترسی دوباره به آن می‌رسید و فایل بارگذاری‌شده برای تیکت می‌توانست مدرک دانش‌آموز شود. اکنون زمینهٔ بارگذاری در پایگاه‌داده ثبت و در زمان استفاده بررسی می‌شود و دسترسی پیوست‌ها تابع وضعیت فعلی رکورد است.
- **اعتبارسنجی و پایداری:** `page/limit` اعشاری خطای ۵۰۰ می‌داد، `null` می‌توانست مقیاس نمره را پاک کند، تاریخ تولد آینده پذیرفته می‌شد، رمز بلندتر از ۷۲ بایت در bcrypt بریده می‌شد، پایهٔ درس/کلاس و ظرفیت سرویس کنترل نمی‌شد و ویرایش هم‌زمان بی‌سروصدا بازنویسی می‌کرد. اکنون اعتبارسنجی صریح، محدودیت بایت و کنترل هم‌زمانی نسخه‌دار (`revision`) با پیام «اطلاعات تازه بارگذاری شد» وجود دارد.
- **رابط:** دکمه‌های عملیات بر اساس مجوز واقعی همان رکورد نمایش داده می‌شوند، گزینه‌های بدون دادهٔ پیش‌نیاز دکمهٔ ثبت نمی‌دهند، گزارش‌ها مقدار «—» را به‌جای صفر گمراه‌کننده نشان می‌دهند، شمارندهٔ اعلان‌ها با خواندن هر مورد به‌روز می‌شود و جدول حضور در موبایل بدون سرریز و بدون نمایش شمارهٔ ولی به دانش‌آموز/ولی دیگران رندر می‌شود.
- **مهاجرت آزمون‌شده:** بازسازی پایگاه‌دادهٔ نسخهٔ یک (بدون ستون‌های تازه) و بررسی حفظ رکوردها، کلاس تاریخی نمرات، زمینهٔ فایل‌ها و دوباره‌اعلان‌نشدن اطلاعیه‌ها.
- **مهاجرت:** پایگاه‌دادهٔ نسخهٔ قبل به‌صورت افزایشی (`ALTER TABLE`) مهاجرت می‌کند؛ کلاس تاریخی نمرات، زمینهٔ فایل‌های موجود و وضعیت اعلان اطلاعیه‌ها بدون حذف داده بازسازی می‌شوند.

## دور دوم بازبینی (۷ اصلاح + ۶ بهبود رفتاری)

بازبینی دوم با ۲۹ آزمون کاوش تازه روی همهٔ نقش‌ها، همهٔ قابلیت‌ها و فعالیت‌های کاربران انجام شد؛ تمرکز این دور بر مواردی بود که دور اول پوشش نداده بود:

- **دور زدن قابلیت خاموش:** مسیر `POST /settings/accounts/create/:resource/:id` پرچم «مدیریت حساب‌ها» را نادیده می‌گرفت و با وجود غیرفعال‌بودن قابلیت، حساب می‌ساخت (پاسخ ۲۰۱ به‌جای ۴۰۳). اکنون کل مسیر پشت همان پرچم است و آزمون `audit3` آن را تضمین می‌کند.
- **یک هویت برای هر پرونده:** اگر رکورد دانش‌آموز/معلم پیوند حساب کهنه داشت ولی حساب از قبل وجود داشت، مسیر ساخت حساب می‌توانست حساب دوم بسازد؛ اکنون ۴۰۹ با پیام راهنما و ترمیم پیوند.
- **ردپای ورودهای ناموفق:** تلاش ناموفق ورود در `audit` ثبت نمی‌شد؛ اکنون `auth.login_failed` با نام کاربری برای بررسی مدیر ثبت می‌شود (بدون افشای وجود/عدم‌وجود حساب در پیام خطا).
- **انتخاب کلاس در صفحهٔ حضور:** انتخاب‌گر کلاس فقط در نخستین رندر مقدار می‌گرفت؛ چون «داده‌های مرجع» ناهم‌زمان می‌رسند، درخواست بدون فیلتر کلاس (برای مدیر، کل مدرسه) ارسال می‌شد و ذخیره با `class_id` خالی شکست می‌خورد. اکنون کلاس پیش‌فرض انتخاب و ذخیره بدون کلاس مسدود می‌شود.
- **حذف با نسخهٔ رکورد:** حذف از رابط، `revision` نمی‌فرستاد و محافظت تعارض را دور می‌زد؛ اکنون نسخه ارسال می‌شود و در تعارض، پیام روشن + بازخوانی فهرست نمایش داده می‌شود.
- **شمارندهٔ صادق قابلیت‌ها:** آمار «قابلیت فعال» در صفحهٔ ماژول‌ها بر پایهٔ نقش بیننده فیلتر می‌شد و قابلیت‌های فعال دانش‌آموز/معلم را برای مدیر «غیرفعال» نشان می‌داد؛ اکنون شمارش مدرسه‌ای است و شمار نقش بیننده جدا نمایش داده می‌شود.
- **اعلان‌های گم‌شدهٔ گردش‌کار:** برای صورتحساب جدید، ثبت پرداخت، تکلیف جدید، آزمون جدید، تخصیص کلاس به معلم و ورود دانش‌آموز تازه اعلانی ارسال نمی‌شد؛ اکنون خانواده و معلم مربوطه مطلع می‌شوند (با احترام به خاموش‌بودن قابلیت مرجع).

پوشش آزمون دور دوم:

- `tests/audit3.test.js` (۶ آزمون): حذف رکوردهای دارای سابقه، کلاس/معلم دارای وابستگی، پرچم مدیریت حساب‌ها، دامنهٔ فهرست‌ها در چهار نقش، مسیر و حریم تیکت‌ها، مالکیت تکلیف/درس در برنامهٔ هفتگی.
- `tests/audit4.test.js` (۱۰ آزمون): چرخهٔ رمز و رمز موقت، متن/نوع/حجم فایل و مجوز دانلود، حریم پاسخ تکلیف، اعلان‌ها و قابلیت خاموش، قواعد حضور، اعتبارسنجی منطقی (تاریخ آینده، کسورات، ظرفیت، تداخل)، CSV دامنه‌دار و ایمن، محدودیت ورود و ابطال نشست، نصب توکن‌دار یک‌باره.
- `tests/audit5.test.js` (۱۳ آزمون): مخاطب اطلاعیه (همه/معلم/کلاس/آینده) و تحویل یک‌باره، عدم نشت اطلاعیهٔ کلاس، اعلان نمره/تکلیف برای دانش‌آموز و ولی، محدودیت اطلاعیهٔ معلم به کلاس خودش، مشاوره/سلامت/انتظام، تغییر ترم جاری، ورود گروهی دانش‌آموز و خطاهای ردیفی، ماندهٔ صورتحساب با ویرایش/حذف رسید، حذف کهنه و ظرفیت‌ها، خاموش‌کردن ماژول/قابلیت در همهٔ مسیرها، خروجی‌های سوئیچ‌دار و بکاپ واقعی، ردپای رویدادها.

## دور سوم بازبینی (پیاده‌سازی کامل پیشنهادهای مدیر مدرسه)

دور سوم، موارد بحرانی و متوسط [نقد مدیر مدرسه](PRINCIPAL-REVIEW.md) را در نسخهٔ ۱.۱ پیاده کرد (به‌جز چند مورد مقیاس/امنیت که در همان سند به‌عنوان پیشنهاد باقی مانده‌اند). آزمون‌های تازه: `tests/round3.test.js` (۱۳ آزمون یکپارچه) و `tests/deploy.test.js` (۴ آزمون مسیر پایه/ساب‌دایرکتوری)، به‌علاوهٔ ۷ جریان مرورگر تازه.

موارد کلیدی و نقطهٔ اطمینان هر یک:

- **نصب در ساب‌دایرکتوری:** `BASE_PATH` در سرور و build؛ `normalizeBasePath` مقدارهای `''`، `'/'`، `school/` و `//a//b//` را به شکل درست درمی‌آورد؛ API زیر `‎<base>/api`، ریدایرکت `/` به `‎<base>/`، کوکی هم‌دامنهٔ مسیر پایه، و ۴۰۴ برای API بیرون از مسیر. آزمون `deploy`.
- **بازیابی پشتیبان:** `POST /settings/backup/restore` فقط برای مدیر و با تأیید رمز؛ پیش از جایگزینی نسخهٔ `pre-restore-*.sqlite` ساخته می‌شود، فایل ناسازگار رد می‌شود، نشست‌ها باطل و در `restore/history` ثبت می‌گردد. آزمون‌ها شامل بازگردانی بانک واقعی و رد رمز اشتباه است.
- **پل پیامک/ایمیل:** صف `outbox` با وضعیت، تلاش دوباره و پشتیبانی کاوه‌نگار/وب‌هوک؛ اعلان غیبت، نمره، شهریه، تکلیف و اطلاعیه؛ ارسال آزمایشی در تنظیمات. آزمون‌ها شامل جایگزینی سرویس‌دهندهٔ ساختگی و بررسی متن پیام فارسی است.
- **رضایت ولی:** فیلدهای `consent_status`/`consent_date`/`consent_note` با گزارش دانش‌آموزان بدون رضایت.
- **کارنامهٔ دوره و چاپ:** `/analysis/report-card/:studentId` (معدل وزنی، درصد حضور، رتبهٔ کلاس) و صفحهٔ چاپی `/print/cards`.
- **ثبت گروهی نمره:** `POST /assignments/grades/bulk` با پاسخ `{created, updated}`؛ فرم یک‌به‌یک حذف شد.
- **مالی:** تخفیف، اقساط، جریمهٔ دیرکرد و گزارش بدهکاران با سن بدهی؛ آزمون‌ها کنترل بیش‌پرداخت و مانده را پس از این تغییرات هم بررسی می‌کنند.
- **مرخصی و ملاقات:** گردش تأیید درخواست ولی/مدرسه (تأیید → ثبت خودکار «موجه»)، بازه‌های ملاقات با ظرفیت و نوبت‌گیری اولیا.
- **کتابخانه:** رزرو، تمدید، جریمهٔ دیرکرد و گزارش امانت دیرکرد.
- **ارتقا و بایگانی:** پیش‌نمایش و اعمال ارتقا/تکرار/فارغ‌التحصیلی با جدول `student_years`.
- **وزارتی و xlsx:** خروجی استاندارد (سناد/وزارت) و `format=xlsx` در فهرست‌ها؛ ورودی/خروجی xlsx با `shared/xlsx.js` بدون وابستگی بیرونی.
- **مرتب‌سازی و عملیات گروهی:** `?sort=&dir=` در فهرست‌ها و `POST /entities/:resource/bulk` با گزارش موفق/ناموفق.
- **تاریخ جلالی:** `JalaliDateField` در همهٔ فرم‌های تاریخ به‌جای ورودی میلادی؛ تبدیل در `shared/jalali.js` و ذخیرهٔ ISO.
- **کارکنان و حضور کارکنان:** پروندهٔ کارکنان غیرآموزشی، حضور و فیش حقوقی.
- **کارهای امروز من:** `/analysis/my-day` — کلاس‌هایی که امروز حضورشان ثبت نشده، تکالیف ارزیابی‌نشده، اقساط سررسید و تیکت‌های باز.
- **روند تحصیلی، وضعیت سرویس و گزارش خطا:** نمودار روند نمره/حضور هر دانش‌آموز، صفحهٔ `/status` و `POST /support/report` عمومی با کد پیگیری.

دو خطای زمان اجرا که فقط با اجرای واقعی مرورگر پیدا شدند نیز اصلاح شدند: نگهبان `loading || !data` در `AnalysisPanels` (تغییر پارامتر و بازگشت دادهٔ null صفحه را از کار می‌انداخت) و `columns.map(...).find(...)` در جدول رزرو کتابخانه (صفحهٔ `library?tab=reservations` با خطای JavaScript بالا نمی‌آمد).

## فروش ماژولار (لایسنس)

`tests/license.test.js` (۷ آزمون) امضای Ed25519، رد لایسنس دست‌کاری‌شده/منقضی/بیگانه، حالت `LICENSE_MODE=off`، برگشت به ماژول‌های پایه در نبود لایسنس، اعمال سه‌لایه (endpoint با کد `LICENSE_REQUIRED`، مسدودشدن سوییچ تنظیمات و پرچم `entitled` در `/api/config`) و کل چرخهٔ CLI (`keygen → issue → inspect`) را پوشش می‌دهد. آزمون‌ها با کلید ساخته‌شده در همان اجرا کار می‌کنند و به کلید واقعی فروشنده وابسته نیستند.

## جریان‌های مرورگر

1. داشبورد، وزیرمتن محلی، RTL، جست‌وجو و پرونده/نمرات/اولیا.
2. ثبت معلم ← ساخت کلاس پایهٔ اول ← ثبت دانش‌آموز ← تحویل نام کاربری/رمز ← تغییر رمز هر دو نقش ← تیکت و پاسخ معلم.
3. حضور فردی و گروهی و دانلود CSV.
4. خاموش و روشن‌کردن ماژول و capability؛ API همان عملیات نیز مسدود می‌شود.
5. تغییر نقش نمایشی و بررسی رکوردهای پنل معلم، دانش‌آموز و ولی.
6. منوی موبایل و جدول، بدون overflow صفحه در ۳۹۰×۸۴۴.
7. نصب مدرسهٔ تازه با ویزارد پنج‌مرحله‌ای، توکن و نمونهٔ امن.
8. رویداد تقویم و ثبت رسید داخل مودال صورتحساب؛ پشتهٔ dialog باز و بسته می‌شود.
9. تحویل فایل با نام فارسی و ارزیابی آن در مودال روی مودال.
10. ساخت حساب معلم موجود پس از فعال‌شدن قابلیت؛ جلوگیری از نمایش دکمهٔ ساخت تکراری.
11. رندر منابع عمومی، گزارش، اعلان، پروفایل و تب‌های تنظیمات بدون خطای JavaScript.
12. خاموش‌بودن «مشاهدهٔ دانش‌آموز»: هدایت به داشبورد و نبود دادهٔ تجمیعی، بدون خطای صفحه.
13. ویرایش هم‌زمان با نسخهٔ قدیمی: نمایش پیام تعارض و بازخوانی، بدون بازنویسی خاموش.
14. قفل تکلیف ارزیابی‌شده و غیرفعال بودن ارسال مجدد تا اجازهٔ معلم.
15. خواندن تک‌به‌تک اعلان و هم‌خوانی شمارندهٔ خوانده‌نشده.
16. عدم نمایش شمارهٔ تماس ولی در جدول حضور برای دانش‌آموز و تناسب صفحهٔ کوچک.
17. انتخاب کلاس پیش‌فرض در صفحهٔ حضور و ثبت موفق وضعیت پس از بارگذاری داده‌های مرجع.

هر تست مرورگر علاوه بر نتیجهٔ جریان، خطاهای pageerror را بررسی می‌کند. داده‌ها و بانک آزمون جداگانه و موقت‌اند؛ اجرای آزمون اطلاعات پیش‌نمایش یا مدرسهٔ واقعی را تغییر نمی‌دهد.

## بازتولید

```bash
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
npm run format:check
npm audit
npm run package:cpanel
```

برای مرورگر موجود، `CHROMIUM_EXECUTABLE_PATH` قابل استفاده است. در محیط محدود این بررسی از Chromium ازقبل‌استخراج‌شده استفاده شد؛ دانلود Playwright CDN در آن محیط ممکن نبود. بستهٔ نصب به این مرورگر و ابزار آزمون وابسته نیست.

آزمون‌ها با `LD_LIBRARY_PATH` و `CHROMIUM_EXECUTABLE_PATH` اجرا شدند (Chromium 153.0.8010.0). مسیر ۳۱۰۰ آزمون مرورگر با `reuseExistingServer` مدیریت می‌شود و در پایان دادهٔ موقت پاک می‌گردد.

## محدودیتِ تأیید

این نتایج **تأیید استقرار روی یک حساب واقعی cPanel، ممیزی امنیت مستقل، تست بار، تست چند worker یا تأیید قانونی حفاظت از دادهٔ کودکان نیستند**. قابلیت‌ها در معماری یک مدرسه/یک فرآیند بررسی شده‌اند. مراحل HTTPS، تک instance، پشتیبان و بازیابی باید روی میزبان مقصد انجام و آزمایش شوند.

پیامک و ایمیل با سرویس‌دهندهٔ ساختگی/صف آزمون بررسی شده‌اند؛ ارسال واقعی به اعتبار سرویس‌دهندهٔ مدرسه وابسته است و باید با کلید واقعی آزمون شود. خروجی وزارتی فایل استاندارد است و **به‌معنای پذیرش رسمی در سناد/شاد نیست**؛ قالب نهایی باید با بخشنامهٔ روز اداره تطبیق داده شود. بازیابی پشتیبان از داخل سامانه، پیوست‌ها (`uploads`) را جایگزین نمی‌کند و باید جداگانه هم‌گام شود.
