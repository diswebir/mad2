# راهنمای گام‌به‌گام نصب روی cPanel

این سند دو مسیر کامل دارد: **۱) نصب نسخهٔ نمایشی (دمو)** و **۲) نصب واقعی بدون دمو**. اگر فقط می‌خواهید سامانه را به کسی نشان دهید، مسیر دمو را برو و بعداً همان فایل‌ها را با تنظیمات واقعی بالا بیاور (بخش ۳).

پیش از شروع: هاست باید **Setup Node.js App** (CloudLinux) یا **Application Manager/Passenger** داشته باشد و Node.js **۲۰.۱۹+** یا **۲۲.۱۲+** روی آن قابل انتخاب باشد. هاست صرفاً PHP کافی نیست و بدون SSH هم می‌شود (همهٔ مراحل با File Manager انجام می‌شود).

---

## ۱) نصب دمو روی cPanel (۱۵ دقیقه)

> این نصب **فقط برای نمایش و فروش** است؛ هرگز دادهٔ واقعی مدرسه داخل آن وارد نکنید.
> نصب دمو روی `NODE_ENV=production` (که Passenger خودش تنظیم می‌کند) هم کار می‌کند
> و نیازی به دست‌زدن به NODE_ENV نیست.

### گام ۱ — بستهٔ دمو را بساز و بردار

```bash
npm ci
npm run package:demo
```

خروجی: `artifacts/madresehyar-demo-cpanel.zip`. داخل ZIP فایل `START-HERE-DEMO.txt` هم هست و همین مراحل را خلاصه می‌کند.

### گام ۲ — پوشهٔ برنامه و پوشهٔ داده

در cPanel → **File Manager**:

1. پوشه‌ای بسازید مثل `/home/CPANEL_USER/madresehyar` **بیرون از `public_html`**.
2. فایل ZIP را در همان پوشه Upload و **Extract** کنید. پس از Extract باید `app.cjs` و `package.json` مستقیماً داخل `madresehyar` باشند (نه یک پوشهٔ تو در تو).
3. یک پوشهٔ جدا برای دادهٔ دمو بسازید: `/home/CPANEL_USER/madresehyar-demo-data` (بیرون از `public_html`). هر وقت این پوشه را خالی کنید و Restart بزنید، دمو از نو ساخته می‌شود.

### گام ۳ — ساخت اپلیکیشن Node

cPanel → **Setup Node.js App** → **Create Application**:

| فیلد                     | مقدار                                            |
| ------------------------ | ------------------------------------------------ |
| Node.js version          | `22.x` (یا `20.19+`)                             |
| Application mode         | هر مقداری؛ دمو به‌صورت پیش‌فرض `Production` است  |
| Application root         | `madresehyar`                                    |
| Application URL          | دامنه یا زیردامنهٔ دمو، مثلاً `demo.example.com` |
| Application startup file | `app.cjs`                                        |

سپس دکمهٔ **Restart** (یا **Run NPM Install** در نسخه‌های قدیمی‌تر) را بزنید. در بسته‌های نسخهٔ ۱.۲.۱ به بعد، **همهٔ وابستگی‌ها (`node_modules`) داخل خود ZIP** هستند و معمولاً نیازی به Run NPM Install نیست؛ فقط اگر لاگ خطای `missing npm packages` یا `Cannot find module` داد، آن دکمه را بزنید یا در ترمینال هاست داخل پوشهٔ برنامه اجرا کنید: `npm install --omit=dev`.

> **زیرپوشه:** اگر می‌خواهید دمو روی `example.com/demo` باشد، در Application URL مقدار `/demo` را بگذارید و `BASE_PATH=/demo` را هم در گام ۴ وارد کنید.

### گام ۴ — فایل تنظیمات `.env`

در **همان پوشهٔ `madresehyar`** (کنار `package.json`) فایلی به نام دقیق **`.env`** بسازید (دکمهٔ New File در File Manager) و این متن را داخل آن بگذارید؛ به‌جای `CPANEL_USER` نام کاربری هاست خودتان را بنویسید:

```dotenv
DEMO_MODE=true
DATA_DIR=/home/CPANEL_USER/madresehyar-demo-data
BASE_PATH=
TRUST_PROXY=1
```

- `BASE_PATH` برای دامنهٔ اصلی خالی می‌ماند؛ برای زیرپوشه مثلاً `/demo` بگذارید.
- اگر `.env` نمی‌سازید، همین مقادیر را در بخش **Environment variables** صفحهٔ اپلیکیشن وارد کنید.
- نیازی به `NODE_ENV` نیست؛ هر مقداری (از جمله `production`) قابل قبول است.

### گام ۵ — اجرا و بررسی

1. **Restart** را بزنید.
2. از همان صفحه، ورودی برنامه (Log) را باز کنید — یا از منوی **Errors** در cPanel. دو خط زیر یعنی نصب سالم است:

```
Vendor: Dis Web Company (شرکت دیس وب) - https://disweb.ir
MadresehYar is ready on port ... (demo mode)
```

3. آدرس سایت را باز کنید؛ در اولین اجرا دادهٔ نمایشی ساخته می‌شود:

| نقش       | نام کاربری | رمز           |
| --------- | ---------- | ------------- |
| مدیر      | `admin`    | `School@1405` |
| معلم      | `teacher`  | `School@1405` |
| دانش‌آموز | `student`  | `School@1405` |
| ولی       | `parent`   | `School@1405` |

روی صفحهٔ ورود، دکمه‌های «یک نگاه به پنل‌های نمایشی» هم هست و می‌توانید بدون رمز بین نقش‌ها جابه‌جا شوید.

### گام ۶ — دموی تمیز برای هر نمایش

- **شروع از صفر:** محتوای پوشهٔ `madresehyar-demo-data` را پاک کنید و Restart بزنید؛ دادهٔ دمو از نو ساخته می‌شود.
- **نصب دوم بدون خراب‌کردن اولی:** یک `DATA_DIR` دیگر بدهید.

### عیب‌یابی نصب دمو

| مشکل                                                         | راه‌حل                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| صفحه ۵۰۰ می‌دهد                                              | لاگ برنامه را بخوانید؛ رایج‌ترین دلیل، اشتباه‌بودن مسیر `DATA_DIR` یا ساخته‌نشدن پوشهٔ داده است. مسیر باید کامل و از `/home` شروع شود.                                                                                                                                                                   |
| `Cannot find module ...` / `ERR_MODULE_NOT_FOUND` / خطای ۵۰۳ | وابستگی‌های npm ناقص است (مثلاً `Cannot find package 'fflate'`). در همان صفحهٔ Setup Node.js App دکمهٔ **Run NPM Install** را بزنید و Restart کنید؛ یا در Terminal هاست: `cd` به پوشهٔ برنامه و `npm install --omit=dev`. اگر باز هم نشد، ZIP جدید (که `node_modules` داخلش است) را دوباره Extract کنید. |
| ۴۰۴ روی زیرپوشه (`example.com/demo`)                         | `BASE_PATH=/demo` را فراموش کرده‌اید.                                                                                                                                                                                                                                                                    |
| داده‌ها قدیمی/کثیف شده                                       | پوشهٔ داده را خالی کنید و Restart بزنید.                                                                                                                                                                                                                                                                 |
| صفحه سفید می‌ماند                                            | در File Manager بررسی کنید `dist/` بعد از Extract وجود داشته باشد؛ نصب دوبارهٔ ZIP مشکل را حل می‌کند.                                                                                                                                                                                                    |

> ⚠️ **دمو = نصب نمایشی.** حساب‌ها رمز عمومی دارند و امکانات نمایشی بازتر است. **هیچ‌وقت دادهٔ واقعی مدرسه را روی نصب دمو وارد نکنید.** برای مدرسهٔ واقعی، بستهٔ اصلی `madresehyar-cpanel.zip` را با `DEMO_MODE=false` نصب کنید.

## ۲) نصب واقعی (بدون دمو)

### گام ۱ — بستهٔ اصلی

```bash
npm ci
npm run package:cpanel      # artifacts/madresehyar-cpanel.zip
```

### گام ۲ — آپلود و ساخت اپلیکیشن

عیناً مثل بخش ۱ (گام‌های ۲ و ۳)، با این تفاوت‌ها:

- پوشهٔ داده: `/home/CPANEL_USER/madresehyar-data`
- Application mode: معمولاً `Production`

### گام ۳ — متغیرهای محیطی واقعی

```dotenv
NODE_ENV=production
DEMO_MODE=false
DATA_DIR=/home/CPANEL_USER/madresehyar-data
TRUST_PROXY=1
MAX_UPLOAD_MB=5
INSTALL_TOKEN=یک-رشتهٔ-تصادفی-حداقل-۲۴-کاراکتری
BASE_PATH=
```

توکن تصادفی:

```bash
openssl rand -hex 24
```

اگر `INSTALL_TOKEN` را خالی بگذارید، برنامه خودش توکن را در `DATA_DIR/install.key` می‌سازد و در لاگ می‌گوید. آن فایل را خصوصی نگه دارید و پس از نصب پاکش کنید.

### گام ۴ — ویزارد نصب

1. آدرس زیر را باز کنید: `https://school.example.com/install` (یا `‎/school/install` در نصب زیرپوشه).
2. توکن نصب را بچسبانید.
3. پنج مرحله را کامل کنید: **بررسی آمادگی → اطلاعات مدرسه → حساب مدیر → انتخاب ماژول‌ها → پایان**.
4. در مرحلهٔ «دادهٔ نمونه»، گزینهٔ **بدون دادهٔ نمونه** را بزنید (برای مدرسهٔ واقعی). اگر دمو را انتخاب کنید، حساب‌های نمونه غیرفعال ساخته می‌شوند و باید رمزشان را بازنشانی و فعال کنید.
5. پس از پایان، با حساب مدیری که ساختید وارد شوید و رمز را تغییر دهید.

### گام ۵ — HTTPS و تنظیم نهایی

1. cPanel → **SSL/TLS Status** → Run AutoSSL؛ سپس در `.htaccess` دامنه، ریدایرکت HTTP→HTTPS بگذارید.
2. در Setup Node.js App مطمئن شوید Passenger فقط **یک نمونه** اجرا می‌کند (`PassengerMaxInstancesPerApp 1` را از پشتیبانی هاست بخواهید). SQL.js در حافظهٔ یک فرآیند است و دو نمونهٔ هم‌زمان روی یک `DATA_DIR` با قفل `school.lock` جلوی خرابی داده را می‌گیرد. محتاطانه: توکن نصب را بعد از نصب از `.env` بردارید.
3. `DATA_DIR` باید بیرون `public_html` و بدون دسترسی عمومی باشد.
4. برای هر فروش/مشتری: لایسنس را طبق [docs/LICENSING.md](LICENSING.md) نصب کنید (`LICENSE_MODE=on` + `DATA_DIR/license.json`).
5. از «تنظیمات → پشتیبان‌گیری» یک پشتیبان بگیرید و یک‌بار مسیر «بازگردانی پشتیبان» را آزمایش کنید.
6. اگر پیامک/ایمیل می‌خواهید: «تنظیمات → پیامک و ایمیل» را پر کنید و «ارسال آزمایشی» بزنید.

## ۳) تبدیل نصب دمو به نصب واقعی

ساده‌ترین راه، نصب واقعی از صفر است (بخش ۲). اگر می‌خواهید همان پوشهٔ برنامه را نگه دارید:

1. از cPanel برنامه را **Stop** کنید.
2. `.env` را واقعی کنید: `NODE_ENV=production`، `DEMO_MODE=false`، `INSTALL_TOKEN=...`، و `DATA_DIR` را به یک پوشهٔ دادهٔ **خالی** تغییر دهید.
3. **Restart**. چون `DATA_DIR` تازه است، ویزارد `/install` دوباره ظاهر می‌شود؛ مراحل بخش ۲ را کامل کنید.
4. پوشهٔ دادهٔ دمو را (که پر از دادهٔ نمونه است) پاک کنید یا خارج از هاست آرشیو کنید.

> هرگز دادهٔ واقعی را روی همان `DATA_DIR` دمو ادامه ندهید؛ حساب‌های دمو رمز عمومی دارند.

## ۴) نصب در زیرپوشه (ساب‌دایرکتوری)

| کار                                                        | مقدار                             |
| ---------------------------------------------------------- | --------------------------------- |
| Application URL در cPanel                                  | `/school`                         |
| متغیر محیطی روی هاست                                       | `BASE_PATH=/school`               |
| اگر خودتان بسته را می‌سازید، پیش از build روی دستگاه توسعه | `BASE_PATH=/school npm run build` |

نتیجه: API زیر `‎/school/api`، دارایی‌ها زیر `/school/`، کوکی نشست محدود به `/school`، و `/` به `/school/` هدایت می‌شود. اگر بعداً به دامنهٔ ریشه برگشتید، فقط `BASE_PATH` را خالی کنید و دوباره Restart (اگر بستهٔ ساخته‌شده را دستی build می‌کنید، build را هم تکرار کنید).

---

## ۵) چه‌چیز در بستهٔ ZIP هست و چه چیز نیست

**در بسته هست:** همهٔ کدها، `dist/` ساخته‌شده، و **`node_modules` کاملِ زمان اجرا** (از نسخهٔ ۱.۲.۱ به بعد) — یعنی روی هاست دیگر نیازی به نصب وابستگی نیست.

**در بسته نیست:** `.env`، پایگاه‌داده، `DATA_DIR/uploads`، توکن نصب و `.git` (این‌ها متعلق به خود هر نصب‌اند). build هم روی هاست انجام نمی‌شود.

## ۶) عیب‌یابی سریع

| نشانه                                               | راه‌حل                                                                                                                                             |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| صفحهٔ سفید / پیام build                             | `dist/index.html` در Application root نیست؛ ZIP کامل Extract نشده یا از پوشهٔ تو در تو اجرا می‌شود.                                                |
| `Another process owns this database`                | بیش از یک instance روی همان `DATA_DIR` اجرا شده؛ همه را Stop و Passenger را تک‌نمونه کنید.                                                         |
| خطای ۴۰۳ برای Origin                                | دامنهٔ نهایی، `TRUST_PROXY` و هم‌مبدأ بودن UI و API را بررسی کنید.                                                                                 |
| خطای ۵۰۳ هنگام بالا آمدن / `Cannot find package`    | `node_modules` ناقص است: **Run NPM Install** + Restart، یا در ترمینال `npm install --omit=dev` داخل پوشهٔ برنامه؛ یا دوباره Extract کردن ZIP جدید. |
| ورود روی HTTP نمی‌ماند                              | در `NODE_ENV=production` کوکی Secure است؛ HTTPS را فعال کنید.                                                                                      |
| Asset 404 در `/school`                              | `BASE_PATH` را هم در build و هم در `.env` ست کنید (بخش ۴).                                                                                         |
| توکن نصب پیدا نیست                                  | `DATA_DIR/install.key` یا مقدار `INSTALL_TOKEN` را ببینید.                                                                                         |
| در دمو پیام «DEMO_MODE must be false in production» | `NODE_ENV` را `development` بگذارید (یا `DEMO_MODE=false` کنید).                                                                                   |
| ماژولی در فهرست نیست یا «خریدنی» است                | لایسنس آن ماژول را نخریده‌اید؛ [docs/LICENSING.md](LICENSING.md).                                                                                  |
| خطای `npm` یا کمبود حافظه هنگام build               | از ZIP آماده استفاده کنید؛ build را روی دستگاه توسعه انجام دهید.                                                                                   |

راهنمای مرجع کامل‌تر (Application root، Passenger، پشتیبان‌گیری، به‌روزرسانی و مهاجرت): [docs/CPANEL.md](CPANEL.md).
