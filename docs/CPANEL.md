# نصب مدرسه‌یار روی cPanel

## ۱. پیش‌نیازهای ضروری

- هاست دارای **Setup Node.js App** (CloudLinux Node.js Selector) یا Application Manager / Passenger باشد. روی پلن صرفاً PHP این برنامه اجرا نمی‌شود.
- Node.js **۲۰.۱۹ یا بالاتر**؛ ترجیحاً ۲۲.۱۲+ و دست‌کم ۵۱۲ مگابایت حافظهٔ در دسترس برنامه.
- **یک instance / worker برای هر DATA_DIR**. SQL.js دیتابیس را در حافظه نگه می‌دارد؛ چند نویسندهٔ مستقل مجاز نیستند. قفل `school.lock` شروع instance دوم را متوقف می‌کند تا داده‌ها خراب نشوند.
- دامنه یا زیردامنهٔ اختصاصی با SSL معتبر؛ مثلا `school.example.com` با Application URL `/`. نصب در زیرمسیر `/school` در نسخهٔ اول پشتیبانی نشده است.
- پوشهٔ قابل نوشتن خارج از `public_html` برای داده‌ها. به MySQL، Redis، npm native build یا دیتابیس با پورت جداگانه نیاز نیست.

> تعداد instance را پیش از نصب با پشتیبانی هاست بررسی کنید. از میزبان بخواهید Passenger را با `PassengerMaxInstancesPerApp 1` در کانفیگ مجاز سرور/VirtualHost تنظیم کند. این دستور را کورکورانه در `.htaccess` نگذارید؛ در برخی هاست‌ها آنجا مجاز نیست و خطای ۵۰۰ ایجاد می‌کند. بدون امکان اجرای تک‌فرآیندی، این نسخه برای آن پلن مناسب نیست.

## ۲. ساخت بسته روی دستگاه توسعه

```bash
npm ci
npm run package:cpanel
```

بسته: `artifacts/madresehyar-cpanel.zip`. فایل hash کنار آن برای بررسی انتقال ساخته می‌شود. رابط و فونت در بسته ساخته شده‌اند؛ بنابراین هاست برای build به حافظهٔ اضافی نیاز ندارد.

## ۳. بارگذاری از File Manager

۱. پوشه‌ای مثل `/home/CPANEL_USER/madresehyar` **خارج از public_html** بسازید.
۲. فایل ZIP را در همان پوشه آپلود و Extract کنید. `app.cjs` و `package.json` باید مستقیماً در Application root باشند، نه یک پوشهٔ تودرتوی اضافه.
۳. فایل `.env.example` را به `.env` کپی کنید یا متغیرهای آن را از پنل Node.js وارد کنید. فایل `.env` در public_html نباشد.

نمونهٔ تنظیمات (نام کاربری و مسیر هاست خود را جایگزین کنید):

```dotenv
NODE_ENV=production
DEMO_MODE=false
DATA_DIR=/home/CPANEL_USER/madresehyar-private-data
TRUST_PROXY=1
MAX_UPLOAD_MB=5
INSTALL_TOKEN=PUT_A_RANDOM_24_PLUS_CHARACTER_TOKEN_HERE
```

توکن بالا فقط یک **جای‌نگهدار** است؛ عین آن را استفاده نکنید. با دستور زیر مقدار تصادفی بسازید:

```bash
openssl rand -hex 24
```

اگر ترمینال ندارید، `INSTALL_TOKEN` را تعیین نکنید؛ برنامه در اولین شروع آن را با مولد رمزنگارانه در `DATA_DIR/install.key` می‌سازد. محتوا را **از File Manager خصوصی** کپی کنید، نه با ساختن مسیر عمومی برای دانلود. این توکن را برای کسی نفرستید.

مجوز پیشنهادی پوشهٔ داده `700` و فایل‌ها `600`، با مالکیت کاربر برنامه است. از `777` استفاده نکنید. مسیر DATA_DIR پس از نصب تغییر نکند مگر با انتقال کنترل‌شدهٔ داده‌ها.

## ۴. ساخت Application

در Setup Node.js App:

| گزینه                    | مقدار                               |
| ------------------------ | ----------------------------------- |
| Node.js version          | 22.12+ یا 20.19+                    |
| Application mode         | Production                          |
| Application root         | `madresehyar` (مسیر طبق پنل میزبان) |
| Application URL          | زیردامنهٔ مدرسه، مسیر `/`           |
| Application startup file | `app.cjs`                           |

از دکمهٔ **Run NPM Install** استفاده کنید. در صورت داشتن ترمینال و فعال‌کردن virtualenv فرمان نمایش‌داده‌شدهٔ خود cPanel را اجرا کنید و سپس:

```bash
cd /home/CPANEL_USER/madresehyar
npm ci --omit=dev
```

در برخی پنل‌ها فقط نصب همهٔ dependencies ممکن است؛ مشکلی برای اجرای برنامه ندارد، اما `npm ci --omit=dev` سبک‌تر است. با بستهٔ آماده نیازی به اجرای Vite یا `npm run build` روی هاست ندارید. `node_modules` محلی را آپلود نکنید.

متغیر PORT را اگر Passenger تعیین می‌کند دست‌کاری نکنید. در اجرای مستقیم خارج از Passenger، PORT مثل `3000` و HOST برابر `0.0.0.0` باشد. ورودی `app.cjs` اولین HTTP server را می‌سازد و با Passenger سازگار است.

**Restart Application** را بزنید. برنامه در حالت Production هرگز DEMO_MODE=true را قبول نمی‌کند. Cookie در تولید Secure و HttpOnly است؛ سایت را با HTTPS باز کنید.

## ۵. ویزارد پنج‌مرحله‌ای

به `https://school.example.com/install` بروید:

1. **بررسی آمادگی:** Node.js، دسترسی پوشه و موتور داده بررسی می‌شوند.
2. **مشخصات مدرسه:** نام، مدیر، سال، شهر و تماس.
3. **حساب مدیر:** نام کاربری لاتین، رمز حداقل ۱۰ کاراکتر و توکن نصب خصوصی.
4. **ماژول‌ها:** انتخاب امکانات و ورود اختیاری دادهٔ نمونه.
5. **پایان:** حساب مدیر ایجاد و نشست او آغاز می‌شود.

نصب در یک تراکنش انجام می‌شود؛ تلاش دوباره پس از تکمیل، وضعیت را بازنویسی نمی‌کند. فایل توکن خودکار پس از نصب پاک می‌شود؛ متغیر INSTALL_TOKEN را نیز از پنل حذف کنید.

اگر «دادهٔ نمونه» را انتخاب کنید، بانک خالی نخواهد بود. **رمز عمومی دمو برای هیچ حساب غیرمدیر در نصب واقعی باقی نمی‌ماند و آن حساب‌ها غیرفعال‌اند.** برای آزمودن یک نقش، در تنظیمات کاربران رمز آن حساب نمونه را بازنشانی و حساب را فعال کنید. حساب‌های واقعی جدید با رمز تصادفی و الزام تغییر رمز ساخته می‌شوند.

## ۶. راه‌اندازی مدرسه بدون نمونه

ترتیب پیشنهادی:

1. اطلاعات مدرسه و سال تحصیلی.
2. ثبت معلم و تحویل امن نام کاربری/رمز موقت.
3. ساخت کلاس و تعیین معلم راهنما؛ برای معلمان دروس مختلف، در برنامهٔ هفتگی کلاس/درس/معلم را تخصیص دهید.
4. ثبت یا واردکردن CSV دانش‌آموزان و اختصاص کلاس.
5. حساب ولی: تنظیمات ← حساب‌های کاربری ← حساب جدید ← ولی و دانش‌آموز مرتبط.
6. دروس، برنامهٔ هفتگی و حضور روزانه.

معلمان فقط کلاس‌های معلم راهنما یا کلاس‌هایی که در برنامهٔ درسی به آنان تخصیص یافته قابل دسترسی دارند. دانش‌آموز و ولی فقط پروندهٔ مرتبط خود را می‌بینند. تیکت دانش‌آموز فقط به مدیر و معلمان کلاس او ارسال می‌شود.

## ۷. پشتیبان و بازیابی

- از تنظیمات ← پشتیبان‌گیری فایل `.sqlite` را دانلود کنید.
- **پیوست‌ها جداگانه‌اند:** پوشهٔ `DATA_DIR/uploads` را با File Manager آرشیو و خارج از هاست نگه دارید.
- نسخهٔ برنامه، `.env` خصوصی و تنظیمات دامنه را نیز نگه دارید. فایل‌های پشتیبان شامل دادهٔ شخصی‌اند و عمومی نباشند.

برای بازیابی:

1. در cPanel برنامه را متوقف و مطمئن شوید هیچ instance دیگری در حال اجرا نیست.
2. از دادهٔ فعلی یک کپی امن بگیرید.
3. فایل پشتیبان را با نام `school.sqlite` در DATA_DIR جایگزین کنید؛ پوشهٔ `uploads` هم از همان پشتیبان باشد.
4. اگر `school.lock` از اجرای قطع‌شده باقی مانده، فقط پس از اطمینان از توقف تمام instanceها آن را حذف کنید. برنامه معمولاً قفل مربوط به PID مرده را خودش تشخیص می‌دهد.
5. مجوزها/مالکیت را بررسی و Application را دوباره Start کنید.
6. ورود، یک پرونده، یک فایل پیوست و گزارش مالی را بررسی کنید.

کپی مستقیم دیتابیس در حالی‌که برنامه در حال نوشتن است توصیه نمی‌شود؛ دانلود مدیریتی یا توقف برنامه را انتخاب کنید. بازیابی destructive از طریق API ارائه نشده تا دانش‌آموز یا درخواست جعلی نتواند بانک را جایگزین کند.

## ۸. رمز مدیر فراموش شده

اگر مدیر دیگری دارید از بازنشانی کاربران استفاده کنید. در غیر این صورت، **ابتدا برنامه را متوقف کنید** و از ترمینال محیط Node.js هاست:

```bash
cd /home/CPANEL_USER/madresehyar
npm run admin:reset -- YOUR_ADMIN_USERNAME
```

نام کاربری موجود مدیر لازم است. یک رمز موقت تصادفی در ترمینال نمایش داده می‌شود. بعد از شروع برنامه با آن وارد شوید و فوراً رمز را عوض کنید. این فرمان endpoint عمومی ندارد و وقتی فرآیند دیگری دیتابیس را در اختیار دارد اجرا نمی‌شود.

## ۹. خطاهای رایج

| مشکل                               | بررسی                                                                                                                              |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| هیچ گزینهٔ Node.js در cPanel نیست  | ارتقای پلن یا میزبانی Node.js لازم است؛ PHP کافی نیست.                                                                             |
| Another process owns this database | تعداد instance بیشتر از یک است، اجرای dev هم‌زمان فعال است، یا قفل باقی مانده. ابتدا همه را متوقف و تنظیم Passenger را اصلاح کنید. |
| خطای EACCES / SQLITE               | مالکیت و مجوز DATA_DIR و فضای خالی دیسک را بررسی کنید.                                                                             |
| خطای npm / حافظه هنگام build       | از ZIP آماده و `npm ci --omit=dev` استفاده کنید؛ build را روی دستگاه توسعه انجام دهید.                                             |
| به‌جای پنل، پیام build دیده می‌شود | `dist/index.html` در Application root وجود ندارد یا ZIP ناقص استخراج شده است.                                                      |
| API خطای 403 برای Origin           | دامنهٔ نهایی، پراکسی و Host را بررسی کنید؛ UI و API باید هم‌مبدأ باشند.                                                            |
| ورود روی HTTP باقی نمی‌ماند        | در تولید Cookie امن است؛ SSL و HTTPS الزامی‌اند.                                                                                   |
| Asset 404 در /school               | برنامه را در ریشهٔ زیردامنه نصب کنید؛ basename سفارشی در نسخهٔ اول نیست.                                                           |
| توکن نصب پیدا نیست                 | File Manager مسیر خصوصی DATA_DIR/install.key یا متغیر INSTALL_TOKEN را بررسی کنید.                                                 |

## حدود استقرار

این راهنما برای یک مدرسه، یک Node process و ذخیرهٔ محلی است. اجرای چند مدرسه، cluster، filesystem شبکه‌ای با چند نویسنده یا ترافیک سازمانی بزرگ نیاز به مهاجرت لایهٔ داده و تست بار دارد. MySQL، درگاه پرداخت، پیامک و اتصال سرویس‌های دولتی در این نسخه وجود ندارند.

## به‌روزرسانی نسخه و مهاجرت پایگاه‌داده

پیش از هر به‌روزرسانی، از `data/school.sqlite` و پوشهٔ `data/uploads` نسخهٔ پشتیبان بگیرید و برنامه را متوقف کنید.

1. فایل‌های نسخهٔ تازه را جایگزین کنید (پوشهٔ `data` را دست‌نخورده نگه دارید).
2. `npm ci --omit=dev` را در Setup Node.js App اجرا و برنامه را Restart کنید.
3. در اولین اجرا، ستون‌های تازهٔ پایگاه‌داده (`revision`، زمینهٔ فایل‌ها، وضعیت اعلان اطلاعیه‌ها و کلاس تاریخی نمرات) به‌صورت افزایشی ساخته و مقادیر قبلی بازسازی می‌شوند؛ هیچ جدول یا رکوردی حذف نمی‌شود.
4. برای اطمینان از مهاجرت، فهرست دانش‌آموزان و یک صورتحساب را باز کنید و در صورت خطا، نسخهٔ پشتیبان را بازگردانید.

نکتهٔ هم‌زمانی: اگر دو مدیر هم‌زمان یک رکورد را ویرایش کنند، ذخیرهٔ نسخهٔ قدیمی با پیام تعارض رد می‌شود و باید صفحه را تازه کنید؛ این رفتار از بازنویسی خاموش جلوگیری می‌کند.
